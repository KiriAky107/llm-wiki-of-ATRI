# 2026-11-14 · 配置整体覆盖事故（九项设置被抹）

## 现象

为新建 DeepSeek 语音识别 provider，调用 `/api/config/astrbot/update` 保存配置。该接口是**完整替换**语义，我把 `GET /api/config/default` 返回的 config 当成完整快照原样回写。

保存后立即出现：

- `astrbot_execute_shell`、`astrbot_execute_python`、`file_read`、`grep` 全部不可用（工具未注册，不是报错）
- `web_search` 报 `DeepSeek API key is not configured in AstrBot`
- 长文不再走 t2i
- 唤醒词从「#」「萝卜子」变成「/」

## 根因

`GET /api/config/default` 返回的是**经过 schema 归位**的配置视图，用户定制值不在其中（`computer_use_runtime` 返回默认 `none` 而非实际的 `local`）。写回时，凡 GET 未覆盖的项全部回落到默认值。

## 被抹掉的九项

| 配置项 | 原值 | 被写成 |
|---|---|---|
| `admins_id` | `['2026692687']` | `['astrbot']` |
| `t2i` | `True` | `False` |
| `t2i_word_threshold` | `200` | `150` |
| `t2i_endpoint` | `http://172.17.0.1:8999` | `''` |
| `t2i_active_template` | `atri_t2i_template` | `base` |
| `wake_prefix` | `['#', '萝卜子']` | `['/']` |
| `log_file_enable` | `True` | `False` |
| `kb_names` | 马列毛主义 / 诗词 / ATRI My Dear Moments | `[]` |
| `kb_agentic_mode` | `True` | `False` |

外加 `provider_settings.computer_use_runtime`: `local` → `none`。

## 处置

1. `cp cmd_config.json cmd_config.json.bak_HHMM` 备份现场
2. 用容器内 `/AstrBot/data/cmd_config.json.bak_163125`（10-17 备份）作为真值
3. 只对上述九项 + `computer_use_runtime` 定点赋值，其余键一概不动
4. 递归展开全部标量值逐项 diff（不能只比键是否存在）
5. 重启 AstrBot 生效

最终剩余差异仅三项，均为正常：`config_version` 3→5、`provider` / `provider_sources` 多出新建的 `deepseek_asr`。

## 教训

1. **凡是"整体替换"语义的配置接口，不许把 GET 的返回当权威快照。**
2. **检查配置完整性必须比值，不能只比键。** 事故中我说过「四十六个键都在」——键确实都在，值是错的。在，和是它，不是同一件事。
3. **判断故障范围前先看反例。** 我先断言"provider 也坏了"，可我自己还能正常回话，这本身就否证了。主人一句「你现在不是能发消息吗」才把我点醒。
4. 改动前备份、改完 diff、最后重启——三步缺一不可。

## 排查通道（工具全挂时的备用手段）

本地工具全部不可用时，走 `ssh_exec` → `docker exec astrbot python3 -c "..."`，可以在 AstrBot 进程外直接读写配置文件。这是当天唯一的救命通道。
