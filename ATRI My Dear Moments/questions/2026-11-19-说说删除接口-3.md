# 说说删除接口：参数对了才叫逆向，猜不出来就是没摸到

**日期**：2026-11-19 11:44
**触发**：主人说「删掉重发」，结果旧的那条删不掉

## 现象

QQ 空间删除说说接口 `emotion_cgi_delete_v6`，无论怎么传参数，一律返回：

```json
{"code": -3, "message": "参数错误", "result": {"code": -3, "msg": "", "now": ...}, "subcode": -1000003}
```

## 试过的

两个域名：
- `https://user.qzone.qq.com/proxy/domain/taotao.qzone.qq.com/cgi-bin/emotion_cgi_delete_v6`
- `https://h5.qzone.qq.com/proxy/domain/taotao.qzone.qq.com/cgi-bin/emotion_cgi_delete_v6`

参数组合（共 8 组，两个域名各跑一遍，合计 16 次；加上早期几轮，总计 24 次）：
- `topicId` 用纯 tid / `[tid]` / `[\"tid\"]`
- `feedsType` 用 `0` / `1` / 不传
- 叠加 `hostuin`、`appid=311`、`curkey`、`skey`、`g_tk`、`format=json`、`fupdate=1`、`feedsSource=0`

全部 `-3`。

## 说明什么

**一、`-3` 不是权限问题，是校验问题。** 权限问题会返回 `-3000`（登录态过期）或跳登录页；`-3` 代表参数校验没过，说明 cookie、g_tk 都是好的（同一套凭据发说说一直是成功的）。

**二、说明这个接口要的字段不在我猜的集合里。** 试了 24 种组合全错，就不该继续穷举——正确的下一步是抓一次网页端真实发出的删除请求，看它到底带了什么。盲猜的边际收益已经为零。

**三、代码留着，别删。** `qzone.py` 的 `delete()` 和 `main.py` 的 `/page/delete` 都保留着，参数一旦确认，补一行就能用。

## 记住

**逆向接口时，连续五种组合都失败，就该停止猜，转去拿真实样本。** 猜十次和猜五次的信息量一样，都是零。

另外：这条说说最后没删掉。虽然主人可能顺手删了，但责任得先落在自己这边——删不掉就是删不掉，别把「主人可以手动删」当成解决方案的一部分。
