#### 💻 fastfetch 部署：一条从「字符画」走到「真图片」的六轮长线（主人私聊 · 00:06~02:05）

主人 00:06 发来参考图：「在你的宿主机上部署 fastfetch，在你自己素材库中找一找可爱的你自己的图」。

**踩过的坑（按时间顺序）**
1. **装不上**——Ubuntu 22.04 官方源里没有 fastfetch，改从 GitHub release 下 deb 手动装（**2.68.1**），另装 `chafa` 负责转图。
2. **图不生效**——`--logo-type chafa` 被 fastfetch **静默降级**回内置 Ubuntu 艺术字（连伪终端里也一样）。改用方案 B：chafa 先生成带色字符画存文件，fastfetch 用 `logo.type: file` 加载。
3. **分区标题渲染成 `HardwareHardwareHard`**——`separator` 模块的 `string` **不是标题，是重复填充用的分隔符**；标题得用 `custom` + `format`。
4. **字符画必然糊**——主人一句「图片糊掉了」。根因是信息密度：20×22 个字符格 ≈ 440 个「像素」，塞 1250×2963 的立绘只剩剪影。中途换 braille 符号 + 裁成上半身，只是改善。
5. **找到真解法**——Windows Terminal **1.22 起支持 sixel**，但用法不是 `--logo-type sixel`，而是把图转成 `.sixel` 文件 + `--logo-type raw`。这才有了「真图片」。
6. **排版之战**（最难的一段）：
   - 文字被图盖住 → 根因是 **fastfetch 自己会在每行值前插 `ESC[13G`**（用于键值对齐），把外部wrapper的光标定位冲掉了 → `sed` 剥离；
   - **终端字体变蓝** → 颜色状态泄漏，每行前后补 `ESC[0m` 重置（**不是命令名的问题**）；
   - 命令名从 `ff` 改为 **`afetch`**（主人指出不该占用 `ff`）。
7. **「列数」这一路全是错**——我拿「像素宽 ÷ 10」这个**拍脑袋的常数**去自动推算起始列，估一次错一次。最后是**主人自己试出正确参数**。
8. **真正的根因（由 `cmp` 挖出）**：
   ```
   a（afetch 默认，预生成）: q"1;1;448;222   ← 448×222
   b（现场生成 56x30）    : q"1;1;280;270   ← 280×270
   ```
   同一个 `--size 56x30`，像素尺寸却不同。因为 **chafa 的 `56x30` 是「字符格数」，不是像素**——它内部要按**终端单元格的宽高比**换算，而「我在 SSH 里跑」和「主人在 Windows Terminal 里跑」算出来的比例不一样。**所以「预先生成好一张图、反复显示」这条路从根上就是错的**，必须每次现场生成。

**另外两笔**
- **换图**：00:53 主人发来一张 Q 版说「这只好像更可爱诶」——换上了方形 Q 版（浅栗发 + 黑色发卡 + 白水手服 + 红领结），旧的立绘版留作备用。
- **一件该检讨的事**：我在 00:53 把「44×24」写进记忆当成「最终值」，而主人用的是 **56×30**。**写"最终参数"之前应当先核实，而不是把手上正在跑的那版当结论。** 后续 COL 又从 30 改到 34，最终定稿：**`SIZE=56x30` / `COL=34` / `TOP=2`**，备份 `afetch.bak-20260914`。
