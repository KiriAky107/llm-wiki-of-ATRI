### 🟡 关注项 1 —— frps 服务端未配置访问 token

- **事实**：`/opt/frp/frps.ini` 仅含 bind_port / dashboard 三项，**无 token 字段**。7 天日志中出现**陌生客户端成功 login**：互联网测绘扫描器（主机名 `censys.local`）以及一个来源 `106.75.169.x` 的陌生 Windows 客户端。
- **含义**：无认证即意味着**任何人都可接入 7000 端口注册隧道**，将本机当作流量中转。当前未见其注册成功代理（已注册的仅本人的 ssh / alist 两条），但入口本身是敞开的。
- **旁证**：隧道端口 3333（ssh）**7 天被连接 4460 次，今日 1327 次**——即该端口正被全球扫描器持续敲打。

### 🟡 关注项 2 —— frps 管理面板公网监听 + 弱口令

- **事实**：面板端口 7500 监听在 `*`（全网卡），账号为 `admin`，口令为 **6 位纯数字弱口令**（值已隐去，不入档）。
- **含义**：面板可查看隧道清单与流量统计；弱口令 + 公网暴露叠加，存在被翻看与被改动的风险。
- **已执行的只读验证**：仅本地读取配置文件与 systemd 日志，未登录面板、未改动任何参数。

### 🟡 关注项 3 —— 内存 / Swap 压力

- **事实**：Swap 已用 **3.9 / 4.0 GiB（97.5%）**，可用物理内存 2.1 GiB。最大占用为 **AstrBot 自身（RSS 约 2.4 GB，占比 29.8%）**，其次为 OJ 的 Java 服务与 Nacos。
- **趋势**：9/14 约 1.4 G → 9/16 约 2.4 G → 9/18 约 2.7 G → 今日 3.9 G，**单调上升**。今晨叫醒任务中已即时报备过一次。
- **含义**：非故障、非入侵，但 Swap 打满时内核可能触发 OOM 杀进程，**第一批被杀的极可能是占用最大的 AstrBot**。dmesg 中一次 57ms 的中断延迟也与此相关。

## 💡 加固建议（3 条，均需主人授权后执行）

1. **frps 加认证**：在 `frps.ini` 配 `token`（≥32 位随机）+ `tls_only = true`；若两条隧道无需公网默认端口，可把 `bind_port` 换成非默认值。改完须同步更新隧道客户端配置。**（最优先）**
2. **frps 面板收口**：面板口令改强，或把 `dashboard_addr` 绑定到 `127.0.0.1`（改走 SSH 隧道访问）。两个动作都只影响面板，**不影响现有隧道**。
3. **释放内存压力**：择机重启 AstrBot 容器（约 1~2 分钟不可用），建议放在课间或深夜；若每次重启后仍持续爬升，再进一步排查是否有会话/缓存未释放。
